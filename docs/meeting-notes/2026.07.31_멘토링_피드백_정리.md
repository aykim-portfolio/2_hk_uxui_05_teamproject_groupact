# Part 1. 강사님 피드백 — 발표 자료 수정사항

발표용 슬라이드 영상을 함께 시청하며 주신 피드백입니다.

## 1. 기획 배경 · 문제 정의 · 가설

| 항목 | 수정 내용 |
|---|---|
| 기획 배경 | 자료화면 보강 → SNS 스크린샷 추가. 민음사 스크린샷은 너무 작으니 **중간에 크게 삽입하는 효과** 사용 |
| 문제 정의 | 슬라이드에는 문제가 **5가지**인데 음성에는 **4개**로 언급됨 → 확인 필요 |
| 문제 정의 (선택) | 발표 시 3개 카드를 분산해서 보여줘도 무방 — 필수 아님 |
| 가설 도출 및 기대효과 | 좀 더 interactive하게 구성 가능 |

## 2. 신규 페이지 추가 — '디자인 리서치'

**'가설 도출' ↔ '사용자 리서치 개요' 사이에 1페이지 신설**

- PoC를 한 장면씩 삽입 (바이브 코딩 + 데모 영상)
- 7개 전부는 아니어도 **주요 내용은 반드시 포함**
- UX Flow 스케치했던 장면들도 추가

## 3. 사용자 리서치 · 페르소나

- **인사이트 직전 슬라이드**: FGI 사진 삽입 + 그 장면의 주요 발언을 quote로 표기
- **페르소나(송소라님) 동영상 삽입**: 출근 / 신문 읽는 모습 / 컴퓨터 업무 / 점심 먹으며 휴대폰 보는 모습
- **페르소나 챗봇 인터뷰 데모 영상** 추가
- **데이터 기반 디자인 경험 강조** (별도로 부각)
  - Looker Studio로 트래픽 감소 발견 → 전문가 멘토(네이버/구글 유입 감소)를 통해 검증
  - 100만 건 데이터를 SQL로 분석해 페르소나 도출
- **50대 남성 중심 독자 페이지**: 우측 카드 상하 위치 변경

## 4. 시장 · 경쟁 분석

- **TAM/SAM/SOM**: 7.9% → **8%** 로 변경
- **경쟁 구도**: 어피티 / 뉴닉 / 디그 / 토스 스크린샷 삽입
- **대응 전략**: 경쟁사 스크린샷 삽입

## 5. 주요 기능 · 시연

- 기능 설명을 읽기 시작할 즈음 **화면 시연 영상으로 대체**
- **스크랩 라이브러리**: 현재 흰색 카드 → 기사 연관 사진을 배경으로 (또는 사진 대신 카드별 색상 차별화)
- **스크랩 카드 공유**: 어필리에이트 마케팅과 같은 구조라는 점 설명 추가
- **기사 및 스크랩 기록**: 스크린샷 중 '앱 설치' 부분 삭제
- **마이페이지**: (가능하면) 리더보드 추가 — 다른 유저의 성취 확인
- **시퀀스 다이어그램**: `10. 클리핑 꾸미기 저장` / `11. 학습 기록` / `12. 강조` 에 설명 추가, 디자인은 **swim lane 형태**로

## 6. 디자인 시스템

- **glass effect**: 카드가 살짝 겹쳐지는 부분 시연 영상 추가
- "기사 위에 뜨는 버튼·툴바를 불투명 카드로 두면 읽던 문단을 잘라먹습니다" → **이 내용 추가 여부 확인 필요**
- **분량 조정**: 기획/PM 직군 지원 시에는 확 줄이거나 부록으로 이동 (디자이너 과정이므로 현재 구성은 OK)
- **semantic colors**: date cell 부분을 읽어주면 됨 *(수정사항 아님, 발표 팁)*

## 7. 개발 · 협업 프로세스 — **보강 필요**

- 디자인 시스템 개발과 함께 **design.md + 바이브 코딩으로 개발한 내용 반드시 추가**
  → 페이퍼토리 앱 디자인과 작동하는 MVP를 어떻게 만들었는지
- **PRD 내용 추가**, Figma Make 및 Claude 사용 강조
- **GitHub / Jira 사용 내용 1페이지 신설**
- 팀 구성 파트: 팀플하는 장면으로 변경 검토

## 8. 영상 · 내레이션 수정

- 색상 설명에서 **hex code 읽는 부분 삭제**
- Lucide → **'루시드'** 로 읽도록 음성 수정
- "한글이 없어서 Open Sans로 대체" 부분 — 무슨 말인지 **대본 확인 필요**

# Part 2. 멘토님 피드백 — 제품 · 기획 관점

## 잘 만들었다고 본 부분

- **AI 모드 · 쉽게 읽기**: 이전에 봤을 때부터 좋은 아이디어라고 생각했는데, 이번에 실제로 반영된 게 좋았다
- **공유하기**: "우리가 저런 기능을 도입한다면 지금 당장 해도 될 정도"로 퀄리티가 괜찮다. 인스타·스레드 공유가 많다는 **수치를 근거로** 만든 점도 좋게 봄
- 팀이 말한 의도(**쉽게 이해 → 기록 → 습관화**) 기준으로 봤을 때 주요 기능 관점에서는 정말 잘 만들었다

## 기획자 관점 피드백

1. **뉴스에만 갇히지 말 것**
   2·30대용 별도 앱이라면 꼭 뉴스가 아니어도 되고, 새로운 콘텐츠로 접근하면 오히려 더 새로운 방식으로 문제를 풀 수 있다

2. **도토리 보상이 약하다**
   스티커 구매·꾸미기만으로는 사용자가 지친다. 쿠폰·이벤트 같은 **실물 혜택 콘텐츠**와 묶으면 "실질적 혜택이 리텐션을 올린다"는 가설을 세워볼 수 있다.
   다만 여러 의견 중 최종 판단은 **PM의 몫**이니 일단 해보고 안 되면 바꾸면 된다

3. **KPI를 먼저 잡고 거기 필요한 콘텐츠를 채워라**
   8월 10일까지 새 기능은 현실적으로 어렵지만, 넥스트를 그리고 싶다면 "무슨 콘텐츠를 넣을까"가 아니라 **"어떤 KPI가 필요한가"**에서 출발할 것

4. **MVP로서는 충분**
   이런 식으로 콘텐츠가 붙어 앱이 커지면 괜찮은 앱이 될 것

## 사용성 지적

- **스크랩 ↔ 기사 동선이 끊긴다** ⚠️ 가장 구체적인 지적
  - 멘토는 스크랩을 "부동산 매물 뉴스처럼 나중에 다시 찾아보려고 저장하는 것"으로 기대
  - 그러나 과거 기사를 다시 보려면 **달력으로 가야 하고**, 스크랩에서 원문으로 돌아가는 길이 없음
  - 사용자가 언제 스크랩했는지 기억할 수 없으니 **스크랩 영역 → 기사로 연결되는 동선 필요**
- **쉽게 읽기가 예전 버전보다 약해 보인다**
  - 저번엔 기능이 더 많다는 느낌이었는데, 지금은 "요약했냐 안 했냐" 차이처럼 느껴진다
  - *(팀 답변: 모바일 가독성 때문에 폰트·배경 차별화를 줄였음)*
- 개별 UI 불편 사항을 하나씩 짚는 건 MVP라 의미 없다고 보고 생략

## 시장 트렌드 연결 (사업 관점)

- **"이 기사가 내 자산에 어떤 영향을 주는가", 호재/악재 판단 = 요즘 증권사들이 가장 많이 준비하는 영역**
  뉴스 공급 계약에서도 AI 활용 허용 여부가 쟁점이 될 정도
- 팩트 자체는 어느 매체나 겹치니, 증권사들도 요약·호재 판단 쪽으로 AI를 쓰려 함
  → **이 트렌드와 접목시키면 발표 흐름과 스토리가 잘 맞을 것**

## 발표 관련

- 25분은 길다. **뒤쪽 디자인 파트는 거의 날려도 된다** (듣는 사람이 디자이너가 아닐 수 있으므로)
- 다만 **반대 조언**도 있었음: 과정 자체가 디자이너 과정이고 채용 JD에 맞춰 조정할 수 있으니,
  → **다 담은 30분 버전은 유지 + 10분 이내 버전을 하나 더 제작**
