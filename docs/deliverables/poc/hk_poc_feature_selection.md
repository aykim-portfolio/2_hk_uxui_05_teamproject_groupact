# PoC 기능 선별 리포트 — 유사기능 통폐합과 필수기능 판별

> 대상: 기능 우선순위 설정 회의 (07.09 회의록 예고 항목) · 작성일 2026.07.13
> 참고자료: `hk_poc_feature_definition.md` 외 PoC 문서 11종, `경제뉴스_SNS_유저유형_인사이트.md`, `한경 현황 분석.md`, `competitor analysis.md`, 07.09·07.10 회의록

**전제** — 사용자조사(SNS 유저유형 분석)는 아직 정식 종료 전이지만, 이 리포트에서는 잠정 완료된 것으로 간주한다. 따라서 Could/Cut 판단, 특히 게임형·캐릭터형 기능에 대한 판단은 실제 조사 결과가 나오면 재검증이 필요한 가설 수준의 선별이다.

**방법론 로드맵** — 01~02 클러스터링(뭐가 겹치나) → 03~04 근거 매핑(누구의 문제인가) → 05 카노 모델(없으면 불만인가, 있으면 감동인가) → 06 Impact-Effort(지금 할 만한가) → 07~08 MoSCoW 확정(그래서 무엇을, 언제)

## 02. 유사기능 클러스터 — "다른 이름, 같은 메커닉"

기능명이 아니라 독자가 겪는 상호작용 구조 기준으로 재정리하면 14개가 7개 클러스터로 줄어든다.

### A. 완독 유도형 게임 리텐션 — 중복 4건
**F03 재판 · F11 픽셀퀴즈/팩토리 · F12 여의도타이쿤 · F14 픽셀배틀**
골격이 동일: ①기사를 읽는다 → ②본문에서 팩트/단서/증거를 얻는다 → ③그것을 게임(법정·퀴즈·타이쿤·배틀)에 입력해야 진행된다. 그래픽 테마만 다르고 "완독해야 진행"이라는 리텐션 로직은 하나.
**근거**: 4벌을 유지하면 공수가 4배지만 독자가 얻는 가치는 동일. 통합본에 먼저 포함돼 합의가 있던 **F03만 남기고 나머지는 백로그 보류**.

### B. 필기·스크랩 학습 도구 — 중복 3건
**F06 한경페이퍼(필기 리더) · F09 형광펜→액션아이템 · F10 Text Miner**
세 프로토타입 모두 "기사에서 중요한 문장을 표시하고 저장·재사용한다"는 동일 니즈. 저장 형태만 다름(지면 필기 유지 / 카드화 / 브라우저 확장).
**근거**: `한경 현황 분석.md`의 "형광펜 없음, 메모 UI 올드함" 페인포인트를 세 각도에서 풀 뿐. F06은 "모바일 웹앱 first" 결정과도 맞는 채택 형태이므로 **F09·F10의 아이디어는 F06에 흡수**하고 별도 프로토타입은 접는다. 특히 F10은 크롬 확장이라는 배포 채널 자체가 방향과 어긋난다.

### C. 캐릭터 육성형 습관화 — 중복 2건
**F01 머니워크 · F02 뉴스 먹는 3D 펫**
둘 다 캐릭터 애착·성장 욕구로 재방문을 유도하는 동일 장치, 세계관만 다름(산책 vs 육성).
**근거**: SNS 인사이트의 "입문×생산 성취 전시 훅"과 방향은 맞지만, 게임 자체가 목적이 되어 뉴스가 배경 소품화될 위험. 통합본에 먼저 반영되고 일상 습관(산책/출퇴근)과 결합 근거가 더 뚜렷한 **F01만 검증**, F02는 보류.

### D. 3D 공간 탐험형 저관여 진입 — 중복 2건
**F07 한경 3D House · F13 한경서재**
동일한 Three.js 쿼터뷰 이동 + 오브젝트 상호작용 패턴, 동일 타깃(저관여 독자).
**근거**: 기술 스택·UX 패턴·타깃이 사실상 동일해 병행 개발 실익 없음. **F07은 모바일 대응(HKGA-78)까지 진행돼 F07 채택, F13 보류**.

### E. 개인화·가치 번역 (단일)
**F04 내 지갑 번역기** — 겹치는 프로토타입 없음. 경제뉴스를 내 자산 영향으로 번역하는 개인화 필터.

### F. 방송-기사 크로스오버 (단일)
**F05 방송 기사 모아보기** — F04와 같은 HTML에 배너로 구현돼 있지만, "영상↔텍스트 독자 교류"라는 목적 자체는 별개.

### G. 독자형 콘텐츠 생산 도구
**F08 뉴스 숏폼 메이커**
초안에서는 "에디터/PD용 제작 도구"로 보고 독자 우선순위 밖에 뒀으나, `경제뉴스_SNS_유저유형_인사이트.md`의 **심화×생산 — 노하우 판매형 전문가** 페르소나(요약앱·템플릿을 직접 만들어 수익화, 예: "바이브코딩 경제뉴스 요약 앱")를 다시 보면 실제 사용자는 독자 자신일 수 있다. F06의 SNS 인증 내보내기가 텍스트 기반 생산을 지원하듯, F08은 같은 니즈를 영상 기반 생산으로 확장한 것.
**근거(수정)**: "이해관계자가 다르다"는 최초 판단은 근거가 약했음 — 아래 03·05·06·07장에 재분류 반영.

## 03. SNS 유저 인사이트로 본 근거

`경제뉴스_SNS_유저유형_인사이트.md`의 4분면(소비/생산 × 입문/심화)에 클러스터를 얹으면:

| | 소비 | 생산 |
|---|---|---|
| **입문** | 눈팅족 — 저변 최대 잠재 유입층. 진입장벽 낮은 큐레이션 필요.<br>→ F07 3D House · F06 용어박스 · F04 영향도 스냅샷 | 동기부여형 인플루언서 — 확산 핵심 동력. "전문가"가 아니라 "나와 비슷한 사람의 성취"가 훅.<br>→ F06 완독도장·마이페이지·SNS 필기 인증 내보내기 |
| **심화** | 투자 실전 소비자 — 실제 투자 판단 자료로 소비, 사용성·정보밀도에 민감.<br>→ F04 자산 맞춤 필터링 · F06 형광펜 학습 | 노하우 판매형 전문가 — 무료 공유→팔로워 확보→유료 전환의 수익화 최종 단계.<br>→ F06 AI 하이라이트 요약 · **F08 숏폼메이커(재분류)** |

F08은 초안에서 4분면 밖에 뒀으나, "노하우 판매형 전문가"가 이미 직접 도구를 만들어 콘텐츠를 생산·수익화한다는 조사 결과를 볼 때 F08이 겨냥하는 사용자는 독자 자신이다. 코딩 없이 기사를 숏폼으로 뽑아주는 F08은 이 페르소나의 진입장벽을 낮추는 기능으로 재분류한다.

반대로 **클러스터 A(완독유도 게임)와 클러스터 C(캐릭터 육성)는 네 칸 중 어디에도 뚜렷하게 들어가지 않는다.** 두 클러스터는 "게임 참여" 행동은 만들지만, SNS 조사에서 관찰된 실제 유입·확산·수익화 경로 어느 단계와도 직접 연결되지 않는다. 이것이 두 클러스터를 Should/Could로 내리는 핵심 근거다.

## 05. 카노 모델 — 없으면 불만인가, 있으면 감동인가

같은 클러스터 안에서도 기능마다 기대 방식이 다르므로, 대표 기능 10개를 기본형(Must-be)·성과형(Performance)·매력적(Attractive)·무관심(Indifferent)·역품질(Reverse)로 재분류.

| 기능 | 카노 유형 | 근거 |
|---|---|---|
| F06 지면재현+필기 | 기본형 | 열독자 기준 당연적 품질. 없으면 이탈 사유, 있어도 감동은 아님 — 페인포인트를 없애는 것뿐 |
| F06 용어박스 | 기본형(입문자) / 무관심(열독자) | 같은 기능이 세그먼트에 따라 유형이 갈리는 사례 |
| F06 완독도장·마이페이지 | 성과형 | 기록이 정교할수록 만족도가 선형으로 오르는 일원적 품질 |
| F06 SNS 필기 인증 내보내기 | 매력적 | 경쟁사(어피티·뉴닉·디그·썰리 등) 어디에도 없는 차별화 포인트, 입문×생산 확산 동력을 직접 생성 |
| F06 AI 하이라이트 요약 | 매력적(양날) | 제대로 작동하면 매력적이나 지금은 mock 수준 — 부정확하면 역품질로 전환 위험 |
| F08 숏폼메이커 (재분류) | 매력적(양날) | 심화×생산 니즈는 실증됐으나 완성도 낮은 대본·TTS는 브랜드 신뢰를 깎는 역품질 위험 |
| F04 지갑번역기 | 성과형(심화 소비자) / 매력적(시장 전체) | 개인화 정밀도가 오를수록 만족 비례 + 이런 필터를 제공하는 경제지가 드묾 |
| F05 방송 모아보기 | 무관심 | 있으면 좋지만 없어도 크게 아쉽지 않음 |
| F07 3D House | 매력적(입문자) / 역품질(열독자·심화 소비자) | 빠르게 훑고 싶은 세그먼트엔 탐험 과정 자체가 방해물이 될 수 있음 — 세그먼트 분리 필요 |
| F03 독자참여재판 | 매력적(게임 선호층, 좁음) / 무관심(대다수) | 정보를 빠르게 확인하고 싶은 다수엔 게임 진입 자체가 시간 소모 |

**정리**: 기본형·성과형은 "확실히 해야 할 일", 매력적 품질은 "차별화 베팅", 역품질 위험이 있는 기능(F07·F06 AI요약·F08)은 세그먼트 분리나 품질 검증이 선행되지 않으면 전체 출시가 위험하다.

## 06. Impact-Effort 매트릭스 — 무엇을 먼저 할 것인가

임팩트는 04장 페인포인트 매핑 개수 + 05장 카노 유형(기본형·성과형 가중), 공수는 각 PoC의 구현 성숙도 기준.

| | 저공수 | 고공수 |
|---|---|---|

- **F08(숏폼메이커)**: 겨냥하는 세그먼트(심화×생산)는 4분면 중 가장 좁아 전체 임팩트는 제한적이지만, 이미 직접 도구까지 만들어 쓰는 고관여·확산력 있는 유저를 정확히 맞춤. AI 파이프라인이 최고 공수인 만큼 Big Bet으로 두되, Must보다는 심화 사용자 한정 베타로 좁혀 검증 제안.

## 08. 결론 및 다음 단계

> 14개 프로토타입은 실제로는 7개의 서로 다른 문제를 풀고 있었고, 그중 3개 문제(완독유도 게임·필기 도구·3D 공간)는 팀 안에서 이미 3~4벌씩 중복 검증된 상태였다.

선별 논리는 네 갈래다.
1. **중복 제거** — 같은 상호작용 골격을 공유하는 프로토타입은 공수가 앞서 있거나 팀 합의가 있는 쪽 하나만 남긴다(클러스터 A·B·C·D).
2. **페인포인트 근접성** — `한경 현황 분석.md`가 실증한 열독자·입문자의 실제 불편을 직접 해소하는 기능(F06, F04)을 Must로 둔다.
3. **품질 성격(카노)** — 기본형·성과형(확실히 해결)과 매력적 품질(차별화 베팅)을 구분한다. 세그먼트에 따라 역품질로 뒤집힐 수 있는 기능(F07·F03·F08)은 세그먼트 분리를 전제로 재검토한다.
4. **공수 대비 실행 가능성(Impact-Effort)** — 임팩트가 커도 지금 자원으로 안 되면 Big Bet으로 순서를 늦추고, 프로토타입이 완성된 Quick Win부터 확정한다.

네 방법론은 서로 다른 질문에 답한다는 점에서 보완적이다 — "뭐가 겹치나"(클러스터링), "누구의 문제인가"(페인포인트·SNS), "없으면 불만인가 있으면 감동인가"(카노), "지금 할 만한가"(Impact-Effort). 이 네 답이 겹치는 지점(F06 필기·완독기록·SNS인증, F04 지갑번역기)만 최종 Must로 남았다.

**회의 전 팀 내부에서 먼저 맞출 것**
- 용어 정리 — 회의록(07.09, 07.10)에서 "열독자/신독자/입문자" 용어 혼재가 지적됨. 이 리포트는 "열독자/입문자" 2분류로 통일했으니 팀 표준 확정 필요.
- 가정의 한계 — 이 선별은 SNS 조사를 "완료된 것으로 가정"하고 진행했다. 특히 Could/Cut의 게임·캐릭터형 기능은 정식 사용자조사 결과와 재대조할 것.
